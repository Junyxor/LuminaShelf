# 阅读器覆盖层与 Android 无障碍树诊断

核对日期：2026-10-17。只读研究，无产品/测试脚本修改，无提交或本地 UI 操作。AOSP 固定 API 35 提交 [`4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3`](https://github.com/aosp-mirror/platform_frameworks_base/commit/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3)；Chromium 固定当天主线 [`c02f9fc984eae63c9712a74025fb58ae4b9c8720`](https://github.com/chromium/chromium/commit/c02f9fc984eae63c9712a74025fb58ae4b9c8720)。后者不是当前云端 WebView 二进制的精确版本证明。

## 父节点不可见，不能直接推导整棵子树不可见

Android `isVisibleToUser()` 只定义**本节点**可见性，没有规定返回 false 时所有后代必然不可见。Chromium 有明确反例测试：CSS `visibility:hidden/collapse` 的父元素中，子元素显式 `visibility:visible` 仍出现在 Blink AX 期望树；但 Android 平台层可能扁平化 ignored 节点，所以这个测试不能单独证明本次 APK 必然暴露了一个 false 父节点与 true 子节点。[Android API 契约](https://developer.android.google.cn/reference/android/view/accessibility/AccessibilityNodeInfo?hl=en#isVisibleToUser()) · [Chromium 测试](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/test/data/accessibility/css/visibility.html#L1-L7) · [期望 AX 树](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/test/data/accessibility/css/visibility-expected-blink.txt#L1-L7)

固定覆盖层的几何关系也不能只按 DOM 父容器判断：Blink 计算 fixed 元素 bounds 时将容器指定为 root web area，另有 fixed 子元素越出 `overflow:hidden` 父容器仍暴露完整 bounds 的测试。**但 fixed/父 bounds 离屏不等于 `isVisibleToUser=false`。**已读取的 Chromium Android 实现返回 `!IsInvisibleOrIgnored()`；Java builder 将 offscreen 独立记入 extras，并说明未被程序隐藏、仅离屏/遮挡的节点仍可能属于 visible。[fixed bounds 容器](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/third_party/blink/renderer/modules/accessibility/ax_object.cc#L7895-L7902) · [fixed/overflow 测试](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/test/data/accessibility/html/bounds-fixed.html) · [Android visible 判定](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/browser/accessibility/browser_accessibility_android.cc#L540-L542) · [offscreen 与 visible 分开处理](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/public/android/java/src/org/chromium/content/browser/accessibility/AccessibilityNodeInfoBuilder.java#L645-L662)

本项目 dumper 当前对 child 要求 `isVisibleToUser()` 才递归；只要存在一个 false 中间节点，它下面所有节点都不会被检查。这是实际剪枝逻辑，移除剪枝、输出每个节点的 visible/bounds/层级，是合理的**诊断对照**，不是已确认修复。系统 uiautomator dumper 也按 child 可见性剪枝，因此两份 XML 同时缺层不能排除此可能；也不能排除 provider 虚拟树尚未更新。缺少 `role=dialog`、`aria-modal` 或焦点迁移本身，尚不足以证明覆盖层为何缺失。[系统 dumper 的剪枝](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/cmds/uiautomator/library/core-src/com/android/uiautomator/core/AccessibilityNodeInfoDumper.java#L220-L233)

## clearCache、refresh 和重连的边界

API 35 `UiAutomation.clearCache()` 清的是该无障碍连接在 `AccessibilityInteractionClient` 中的缓存；`root.refresh()` 重新查询的是这个节点，不是命令 WebView 重建整棵虚拟 AX 树。Chromium provider 自己还保存 Java `mNodeInfoCache`，并单独实现清理接口、复用/更新节点的路径。因此“framework cache 已清”不能证明 renderer/provider 缓存已重建。[framework 缓存](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/core/java/android/app/UiAutomation.java#L523-L534) · [单节点 refresh](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/core/java/android/view/accessibility/AccessibilityNodeInfo.java#L1196-L1218) · [Chromium 独立缓存及复用](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/public/android/java/src/org/chromium/content/browser/accessibility/WebContentsAccessibilityImpl.java#L1206-L1226) · [缓存节点更新](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/public/android/java/src/org/chromium/content/browser/accessibility/WebContentsAccessibilityImpl.java#L1330-L1376)

底层 `UiAutomation` 允许断开后再连接：disconnect 清旧 connection ID/回调线程，connect 新建回调线程和 client generation。这能建立新的自动化服务连接，适合作为诊断，但**没有“强制重建 WebView DOM/AX provider”保证**。Chromium 的服务状态变化只触发 `refreshNativeState()`，缓存清理和 renderer 自动禁用各有条件，并非每次重连都无条件重建树。[connect](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/core/java/android/app/UiAutomation.java#L362-L385) · [disconnect](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/core/java/android/app/UiAutomation.java#L437-L461) · [Chromium 状态变化入口](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/public/android/java/src/org/chromium/content/browser/accessibility/WebContentsAccessibilityImpl.java#L1430-L1435) · [有条件清理/禁用](https://github.com/chromium/chromium/blob/c02f9fc984eae63c9712a74025fb58ae4b9c8720/content/public/android/java/src/org/chromium/content/browser/accessibility/WebContentsAccessibilityImpl.java#L1058-L1113)

**不能重复调用同一个 `UiAutomationShellWrapper` 的 connect。**其 `HandlerThread` 是一次创建的字段，disconnect 只 quit；再 connect 会重复 start 这个线程，而且无条件再次 `Looper.prepareMainLooper()`。即使另建 wrapper，同进程已准备过 main looper 也有二次准备风险。最隔离的对照是退出当前 dump 的 `app_process`、另起进程；若需要同进程仅重连，须保持 wrapper 的 handler 存活，只对底层 `UiAutomation` 做 disconnect/connect，而不是调用 wrapper 第二次 connect。不要同时运行多个自动化会话。[wrapper 生命周期](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/cmds/uiautomator/library/testrunner-src/com/android/uiautomator/core/UiAutomationShellWrapper.java#L17-L37) · [wrapper disconnect](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/cmds/uiautomator/library/testrunner-src/com/android/uiautomator/core/UiAutomationShellWrapper.java#L66-L76) · [main looper 二次准备异常](https://github.com/aosp-mirror/platform_frameworks_base/blob/4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3/core/java/android/os/Looper.java#L130-L137)

## 同一 APK 的诊断判据

先云跑不剪枝的遍历，保留所有可见性与祖先路径；若出现阅读器节点，定位是哪一级剪枝造成遗漏。若仍完全没有阅读器，再以新的 dump 进程/底层新连接作对照，分别记录截图与 XML 时间、WebView 版本。不可因为无剪枝树里出现隐藏 DOM 的书名就判通过；继续保留实际正文、可交互控件及可见状态的原验收要求。此次未运行云端实验，没有宣布当前剪枝假说或重连方案已解释实际故障。
